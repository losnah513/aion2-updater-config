ARCANA_COMPASS.txt
최신 기준: ARC-0.3.03 · 260620_01
이 파일은 ARCANA 프로젝트의 단일 나침반 파일이다.
다음 채팅방에 ZIP을 업로드하면 GPT는 이 파일을 먼저 확인해야 한다.

============================================================
0. 최상위 운영 규칙
============================================================

- 루트 최상위 텍스트 파일은 원칙적으로 아래 3개만 유지한다.
  1) ARCANA_COMPASS.txt : 규칙 / 작업 루틴 / 다음 채팅방 전달 프롬프트
  2) CHANGELOG.txt : 날짜별 작업 내역 / 코드 감사 요약
  3) MODIFIED_FILES.txt : 이번 ZIP에서 실제 변경된 파일

- 규칙 파일을 v2, v3처럼 계속 늘리지 않는다.
- 규칙이 바뀌면 이 파일 안에서 갱신한다.
- 이전 규칙은 삭제하지 않고 아래 형식으로 남긴다.
  예: ~~이전 규칙~~ (폐기: ARC-0.3.02 · 260615_03)
      새 규칙

- 사용하지 않는 코드는 삭제한다.
- 필요 없어지는 파일은 루트에 방치하지 않는다.
- 필요 없어진 파일은 arcana/_docs/legacy/로 이동하거나, 최소 폐기 안내만 남긴다.

============================================================
1. 작업 시작 루틴
============================================================

사용자가 수정/기능 추가를 요청하면 바로 코딩하지 않는다.
반드시 아래 순서를 따른다.

1. 수정 내용 확인
2. 원인 분석
3. 해결 방안 모색
4. 해결 방법 제시 리포트
5. 사용자 승인
6. 기존 작업물 감사
7. 수정 / 추가 / 삭제 분류
8. 기존 권한 회수
9. 실제 수정
10. 검수
11. 결과물 ZIP 생성

작업 시작 전 확인:
- 오늘 날짜 확인
- 최신 ZIP 확인
- CHANGELOG.txt 확인
- MODIFIED_FILES.txt 확인
- 오늘 작업 순번 확인

파일명 규칙:
- arcana_ARC-버전_YYYYMMDD_순번.zip
- 순번 뒤 설명 문구 추가 금지

화면 표기:
- ARC-0.3.02 · YYMMDD_순번

============================================================
2. 코드 작업 규칙
============================================================

새 CSS/JS를 덮어쓰기식으로 추가하지 않는다.
반드시 기존 코드 위치를 먼저 찾는다.

분류 기준:

[수정]
- 기존 권한 파일이 이미 존재하는 경우 그 파일을 수정한다.

[추가]
- 기존 권한이 없는 경우에만 새 파일을 만든다.
- 새 파일을 추가할 때는 왜 추가했는지 MODIFIED_FILES.txt에 기록한다.

[삭제]
- 사용하지 않는 코드와 중복 권한 코드는 삭제한다.
- 단, 파일 자체가 필요 없어질 경우 루트에서 삭제하거나 방치하지 말고 legacy 처리한다.

절대 금지:
- 문제 발견 → 새 CSS 추가 → 기존 CSS 방치
- 문제 발견 → 새 JS 추가 → 기존 JS 방치
- 구 코드를 주석 처리한 채 실행 파일에 방치

4. Prism Aura / 효과 권한
============================================================

효과 권한 파일:
- arcana/css/components/prism-aura.css

담당 범위:
- 액티브 스킬 16/20 선택 효과
- 스킬 클릭 푸딩 효과
- 저장 완료 카드 빗금 / 채도 감소
- 저장 완료 카드 외곽 테두리 흐름
- CTA 색감 보조

중요 규칙:
- 테두리를 따라 빛이 돌아야 한다.
- 버튼이나 카드 뒤에서 큰 프리즘 판이 회전하면 안 된다.
- 빛은 테두리 레이어에만 존재해야 한다.
- 20레벨 / 16레벨 뱃지는 스킬명을 덮으면 안 된다.
- 스킬 버튼 내부 구조는 [아이콘] [스킬명] [오른쪽 뱃지영역]을 기준으로 한다.
- 뱃지는 오른쪽 상하 2줄 구조를 사용한다.

저장 완료 상태:
- 빗금 배경
- 채도 감소
- 수정하기 버튼 전환
- 카드 외곽을 따라 흐르는 Prism Aura

적용 대상:
- 액티브 스킬
- 반지 옵션
- 현재 아르카나

6. 클래스 선택 규칙
============================================================

- 상단 클래스 선택 버튼은 1개만 존재한다.
- 버튼 클릭 시 카드 회전형 클래스 선택 모달을 연다.
- 확인 버튼을 누르기 전까지 클래스 변경을 반영하지 않는다.
- 초기 로딩 전/후 버튼 모양이 달라지면 안 된다.

============================================================
7. 저장 시스템 규칙
============================================================

- 저장 버튼을 누른 값만 영구 저장한다.
- 저장하지 않은 임시 선택값은 F5 / Ctrl+F5 / 재접속 시 복원하지 않는다.
- UI 표시값과 내부 state가 불일치하면 분석 시작 금지.
- 저장 완료 후 수정하려면 수정하기 버튼을 눌러야 한다.

8. 추천 엔진 규칙
============================================================

기본 계산:
- 캐릭터 기본 스킬 레벨 = 10
- 데바니온 = +4
- 기본 상태 = 14
- 20레벨 목표 = +6 필요
- 16레벨 목표 = +2 필요
- 아르카나 전체 = 36포인트
- 반지 2개 합산 = 6포인트
- 총 예산 = 42포인트

추천 우선순위:
1. 사용자 지정 20레벨 목표 달성
2. 사용자 지정 16레벨 목표 달성
3. 저장된 현재 아르카나 반영
4. 저장된 반지 옵션 반영
5. 부족분만 자동 반지 활용
6. 21레벨 이상 초과 조합 폐기
7. 목표 달성 후 남는 슬롯은 임의 스킬 추천 금지
8. 남는 슬롯은 '스킬 여유' 또는 '자유 선택'으로 표시

Lv4 규칙:
- Lv4는 목표 달성에 꼭 필요한 경우에만 사용한다.
- 스킬 포인트에 여유가 있으면 Lv4를 강제하지 않는다.
- 여유가 있으면 3/2/2/1/1 등 분산 투자를 우선한다.
- 20레벨 목표 7개일 때만 성배/양피지/나침반/천칭 Lv4 앵커 조건을 적용한다.
- 20레벨 목표가 6개 이하라면 모든 아르카나에 Lv4가 반드시 들어갈 필요는 없다.

20/16 예산:
- 20레벨 7개 = 42포인트, 16레벨 추가 없음
- 20레벨 6개 = 36포인트, 16레벨 최대 3개
- 20레벨 5개 = 30포인트, 16레벨 최대 6개
- 20레벨 4개 = 24포인트, 16레벨 최대 9개

아르카나 매핑:
- 성배 = 액티브 F~Q + 패시브 F~O
- 양피지 = 액티브 F/H/J/L/O/P
- 나침반 = 액티브 G/I/K/M/N/Q
- 종 = 패시브 F/H/J/L/N
- 거울 = 패시브 G/I/K/M/O
- 천칭 = 액티브 F~Q + 패시브 F~O
- 모든 클래스는 같은 아르카나 규칙을 사용한다.
- class_skill_db의 skill_db_ 접두어는 시트 DB 키로 유지한다.

10. 다음 채팅방 전달 프롬프트
============================================================

다음 채팅방 GPT는 이 ZIP을 받으면 다음 순서로 시작한다.

1. ARCANA_COMPASS.txt를 먼저 읽는다.
2. CHANGELOG.txt를 읽고 최신 작업 흐름을 확인한다.
3. MODIFIED_FILES.txt를 읽고 직전 수정 파일을 확인한다.
4. 사용자의 요청을 받으면 바로 작업하지 말고:
   - 수정 내용 확인
   - 원인 분석
   - 해결 방안 제시
   - 승인 후 작업
   순서로 진행한다.
5. 새 파일을 만들기 전 기존 파일의 권한을 감사한다.
6. 중복 코드를 남기지 않는다.
7. ZIP 결과물은 지정된 파일명 규칙을 따른다.

10. KINOJO 공통 UI 동기화 규칙
============================================================

- KINOJO INFO와 ARCANA는 같은 사이트군처럼 보이도록 공통 탑바/메뉴바/로딩 스피너를 공유한다.
- ARCANA의 기존 클래스 선택 버튼은 제거하지 않고 공통 탑바 아래 액션바 역할로 축소한다.
- KINOJO 통합 이후 공통 UI/Auth는 ../ui/kinojo-common-ui.css, ../ui/kinojo-common-ui.js, ../ui/kinojo-admin-panel.js, ../core/kinojo-auth.js가 담당한다. arcana 내부에는 복제 공통 UI/Auth 파일을 두지 않는다.
- 공통 로딩 스피너는 흰색 레일 + 파란색 이동 구간 2색 구조를 사용한다.
- 스피너를 새로 여러 개 만들지 말고 loadingOverlay.js에서 공통 스피너 클래스를 호출한다.
- KINOJO 공통 UI를 수정할 때 ARCANA용 경로(hall-of-fame/sanctuary/arcana 상대 경로)를 반드시 확인한다.
