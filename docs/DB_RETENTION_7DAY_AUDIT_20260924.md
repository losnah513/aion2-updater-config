# DB 원본 7일 보존 검토 — 2026-09-24

운영 DB·현행 함수 읽기 전용 조사. 이 문서는 7일 일괄 삭제 허가가 아니다.

## 판정

교체된 조회 스냅샷과 중복 성공 원본은 새 정상본·파생 요약이 확인되면 7일보다 빨리 정리할 수 있다. 사용자가 요청한 장기 보존 대상은 주·월간 아이템 레벨과 전투력의 **수치 요약**이며, 오래된 조회 원문 자체가 아니다. 현행 코드가 7일 초과 원문을 참조하는 부분은 작은 현재 상태·비교 수치로 분리하거나 조회 실패로 처리한 뒤 원문을 정리해야 한다. 참조가 존재한다는 사실만으로 오래된 원문 보존 정책을 만들지 않는다.

주간 경계는 사용자 설명의 “수요일~화요일”을 정확히 구현하면 **Asia/Seoul 수요일 06:00부터 다음 수요일 06:00 직전**이다. 수요일 00:00~05:59 조회는 이전 주에 속한다. 현행 `public.kinojo_aion_week_window`가 이 경계를 사용한다.

현행 `public.kinojo_character_growth_raw_cleanup_v443`은 `character_history`와 `growth_reviews`를 KST 출처일 30일 보관한다. 7일로 바꾸려면 순위의 마지막·직전 숫자와 현재 리뷰 상태를 먼저 보존하고, HOF의 지연/과거 재생성 범위를 결정해야 한다. 단순 상수 변경은 안전하지 않다.

권장 실행 순서: ① 칭호는 마지막 공식 조회만 사용하고 실패를 그대로 표시, ② 현재 기능이 필요한 값만 별도 상태·진단 요약으로 고정하고 오래된 원문 포인터를 제거, ③ 순위 마지막·직전 숫자를 최소 current state에 고정, ④ 검증된 주간·월간 요약과 게시 HOF를 유지하면서 나머지 성공 raw/history를 7일 기준으로 정리. 사용자는 이 정리 범위의 새 백업을 생략하고 복원 불가능성을 감수하기로 했다. 대상·참조·결과 검증은 계속 수행한다.

## 다음 실행 단계 — SQL512

교체된 정상 조회가 있고 현재 Master·스킬·stat·요청·관리자 Target·미완료 Job·Batch·미동기화 payload·실패 시트 큐가 참조하지 않는 스냅샷만 작은 배치로 정리한다. 연결된 동기화 완료 payload는 먼저 압축 진단 결과를 자체 행에 보존한 뒤 원문 링크를 해제한다. 새 조회로 대체되면 7일을 기다리지 않는 후보이며, **7일 초과 원문 전체 정리는 아니다**.

운영 SQL512은 설치됐지만 최초 `enabled=false`, `backup_verified_at=NULL`이라 삭제 호출은 `BACKUP_NOT_VERIFIED`를 반환했다. 적용 직후 dry run 첫 배치 후보 50건, 삭제 0건을 확인했다. 사용자의 백업 생략 결정 뒤 SQL513은 `backup_waived_at`을 추가했고, 삭제는 수동 트랜잭션에서만 잠시 활성화했다. 나머지 7일 초과 원문, 특히 관리자 상세 Target 연결과 마지막·직전 수치의 참조는 후속 분리가 필요하다.

SQL512 수동 배치는 교체된 스냅샷 14,406행을 삭제했다. 후보 잔여 0, 연결 payload 중 진단 캐시 14,023행, Master·스킬·stat·Target 깨진 참조 0, 제어 `enabled=false`를 확인했다. 대상 표의 VACUUM FULL 이후 운영 DB는 449,236,115B였다. 삭제한 원문은 복원할 수 없다.

SQL514는 7일을 넘긴 교체된 정상 스냅샷의 행과 관리자 Target 연결을 보존하면서 원문을 작은 수치·식별 요약으로 치환한다. 수동 배치로 9,998행을 요약해 잔여 후보 0, 전체 진단 캐시 24,021행, 깨진 Target 참조 0, 제어 `enabled=false`를 확인했다. VACUUM FULL 이후 운영 DB는 **438,848,659B**로, 390,000,000B 목표까지 **48,848,659B** 남았다. 7일 초과 스냅샷 6,735행은 현재 참조·미동기화 등의 보호 조건 때문에 대상에서 제외됐다.

다음 후보 조사에서 7일 초과 payload 30,104행 중 현재 Master·stat·ranking·관리자 Target·history·캐릭터별 최신 payload가 참조하지 않는 동기화 완료 행은 15,890개(논리 행 크기 약 24.97MB)다. 모두 종료 세션에 속하며 활성 Job 참조는 0이다. 현재 주의 HOF 계산은 KST 수요일 06:00부터이고 이 후보는 7일보다 오래되어 현 주 밖이다. 삭제를 실행하기 전 과거 복구 함수, 이벤트 재처리 및 실패 큐의 추가 의존성을 분리·검증해야 한다. 이 수치만으로 목표 용량 달성을 보장할 수 없으며, 전체 7일 원본 정책도 아직 완료되지 않았다.

## 후속 실행 — SQL515~517

SQL515는 7일 초과 동기화·성장 검토 완료 payload라도 **세션 종료 30일이 지난 후에만** 행을 삭제한다. 완료 실행 관리자 디버그가 세션별 payload 개수를 직접 읽기 때문이다. 현재 Master/PVE/PVP, stat, ranking, history, 관리자 Target, 캐릭터별 최신 재처리 행, 현재 snapshot 출처, 미완료 Job·Batch, 실패 시트 큐를 보호한다. 첫 50행과 후속 배치에서 총 **14,057행**을 삭제했고 후보 잔여 0이다. VACUUM FULL 후 DB는 **404,278,419B**였다. Master·stat 전체 해시(`cdfcf1af3ede71aa249333600dd074cb`, `a55a0e0b37aa84741d72792771d5cb27`), Target 13,711·history 4,521·성장 rollup 5,277·이번 주 HOF 후보 169행은 전후 동일하다.

SQL516은 접수 이벤트와 종료 세션이 각각 30일을 지난 경우에만 오래된 이벤트를 삭제한다. 미완료 Job·Batch와 실패 시트 큐가 남은 세션을 보호한다. **17,151행**을 정리해 후보 잔여 0, 접수 이벤트 31,787→14,636행, 관리자 Target·성장 rollup 행 수 불변을 확인했다. 해당 표 VACUUM FULL 후 운영 DB는 **388,500,627B**로, 목표 390,000,000B보다 **1,499,373B 낮다**. 이번 SQL515~516에서 50,348,032B를 순회수했다. 삭제 대상의 새 백업은 사용자의 생략 결정에 따라 만들지 않았으며 복원은 보장하지 않는다.

SQL517은 백업 생략 기록을 확인한 뒤 기존 교체 스냅샷 정리와 새 7일 스냅샷 요약·30일 이후 payload·접수 이벤트 정리를 10분 간격의 서로 다른 분에 예약했다. 네 작업 모두 활성, 제어 `enabled=true`, 함수별 최대 50행·15초·잠금 대기 500ms다. 회귀 테스트는 각 대상의 보존 조건·비활성 gate·rollback과 예약의 생략 기록 gate를 검증했고 PR #466~#468의 CI가 통과했다.

**남은 정책 작업:** 현재 Master·스킬·stat·최신 재처리 출처 및 관리자 상세에 걸린 7일 초과 snapshot/payload는 보호 상태다. `character_history`/`growth_reviews`의 30일 원본과 순위 직전 수치도 별도 최소 상태로 분리해야 사용자가 의도한 전체 원본 7일 정책을 완성할 수 있다. 이번 390MB 달성은 이 작업의 완료를 뜻하지 않는다. 용량 여유가 약 1.5MB라 정상 수집 뒤 일시적으로 다시 목표를 넘을 수 있으며 예약 실행과 물리 파일 크기를 계속 관측해야 한다.
