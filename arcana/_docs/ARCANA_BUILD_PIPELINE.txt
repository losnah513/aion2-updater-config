ARCANA BUILD PIPELINE
공식 제작 루틴 / 공사-감리 방식

[목적]
ARCANA UI 작업은 결과물 완성 후 한 번에 확인하는 방식이 아니라,
공사 → 감리 → 승인 → 다음 공사 순서로 진행한다.
이 문서는 이후 모든 ARCANA 작업의 기본 프롬프트이자 검수 기준이다.

[최상위 원칙]
1. 최신 작업물을 기준으로 수정한다.
2. 기능을 새 파일로 덮어씌우지 않는다.
3. 실제 담당 파일을 먼저 감사한 뒤 수정한다.
4. 한 기능은 한 담당 파일에서 관리한다.
5. 작업 중간 단계마다 감리 항목을 작성한다.
6. 사용자 승인 없이 다음 공정으로 넘어가지 않는다.
7. 버튼/카드/영역 크기 잠금 규칙을 우선한다.
8. Apps Script / Extension 수정 여부는 없음이어도 반드시 기록한다.

[STEP 0. 작업 전 감사]
- 기준 ZIP 확인
- 실제 담당 CSS/JS 확인
- 같은 기능을 여러 파일이 동시에 관리하는지 확인
- 죽은 CSS/JS 및 임시 오버라이드 확인
- 버전 관리자 기준 확인

[STEP 1. 부분 공사]
예: 쇼케이스 창 크기, 버튼 위치, 카드 정적 배치, 공전, 자전 등
작업은 한 번에 한 공정만 진행한다.

[STEP 2. 감리]
각 공정 완료 후 아래 항목을 확인한다.
- 레이아웃 침범 없음
- 기존 버튼 시스템 영향 없음
- EFFECT_FINAL 영향 없음
- SELECT BUTTON 영향 없음
- 모바일 1Tap / 2Tap 규칙 영향 없음
- 담당 파일 내부 수정으로 완료되었는지 확인

[STEP 3. 승인]
사용자 확인 후 다음 공정으로 넘어간다.

[STEP 4. 최종 감사]
- 죽은 CSS 없음
- 죽은 JS 없음
- 덮어쓰기식 CSS 없음
- 버전 갱신 완료
- WORK_LOG 갱신 완료
- MODIFIED_FILES 갱신 완료
- Apps Script 수정 여부 기록
- Extension 수정 여부 기록

[SHOWCASE REBORN 전용 공정]
01_SHOWCASE_WINDOW
- 쇼케이스 창 크기/상중하 영역/버튼 위치 정리

02_SHOWCASE_LAYOUT
- 이미지 기준 정적 카드 배치 완성

03_SHOWCASE_EXPANDABLE
- 새 클래스 추가 시 자동 합류 가능한 배열 기반 구조 확인

04_SHOWCASE_ORBIT
- 전체 카드 공전 추가

05_SHOWCASE_WOBBLE
- 카드 개별 탄성 자전 추가

06_FINAL_AUDIT
- 준공검사

[절대 보호 대상]
- EFFECT_FINAL
- 액티브 스킬 버튼
- 푸딩 효과
- 혜성 테두리 효과
- BUTTON_SYSTEM
- 중앙 진입 UX
- 모바일 1Tap / 2Tap 인터랙션 규칙
