## 완료 기능

### 1. 99장 이벤트 묶음

- 정식 이벤트 variant당 최대 99장을 선택·저장한다.
- 라이브러리와 순서 목록은 24장 단위 창 렌더링, 검토는 12장부터 추가 렌더링한다.
- 썸네일은 `loading=lazy`, `decoding=async`를 사용하며 미리보기는 원본 전신을 `contain`으로 보여 준다.
- 기존 1회 업로드 상한 3장은 유지한다. 99장은 업로드 상한이 아니라 이벤트 묶음 선택 상한이다.

### 2. 캐릭터 영구 ID와 대표 이미지

- 자산 연결 정본은 `character_master.id`다. 이름은 표시·검색 값이고 관계키로 사용하지 않는다.
- 동명이인은 서버·종족·직업을 함께 표시하고 후보를 명시적으로 선택한다.
- 업로드 시 캐릭터를 연결하지 않으면 `미연결 업로드 확인`을 체크해야 한다.
- 라이브러리에서 연결 검색·변경·해제, 연결/미연결/대표 필터를 제공한다.
- 대표 이미지는 `character_id + format_code`마다 최대 한 장이다. 지정·교체·해제는 하나의 Server 트랜잭션으로 처리한다.

### 3. 이벤트 없는 자동 라이브러리 순환 풀

- 자동 풀은 기본 OFF이며 기존 라이브러리 전체를 자동 공개하지 않는다.
- 관리자가 명시적으로 고른 `READY` 자산만 최대 99장까지 사용한다.
- 서버 노출 우선순위는 `게시 가능한 정식 이벤트 → 활성 자동 풀 → 기존 기본/레거시 배너`다.
- 정식 이벤트가 하나라도 유효하면 같은 페이지/슬롯의 자동 풀은 노출하지 않는다.
- 자동 풀 내부 순서는 서버 셔플 백이다. 같은 주기에서 모든 항목을 한 번씩 사용하고 다음 주기를 새로 섞는다.
- 페이지·슬롯·일정·유지 시간·전환 시간·효과·방향을 설정할 수 있다.

### 4. 선택적 캐릭터 이름 합성

- `캐릭터 이름 표시`는 기본 OFF다.
- ON이면 원본 자산과 캐릭터 이름을 정확한 MAIN 또는 SIDE 크기의 WebP로 합성한다.
- 파생 합성본 등록이 모두 끝난 뒤에만 풀을 활성화할 수 있다.
- 원본은 보존하고 게시 Manifest는 합성 완료된 파생 자산을 한 장의 배너 이미지로 사용한다.
- 저장하지 않은 변경이나 누락된 합성본이 있으면 활성화 요청을 차단한다.
