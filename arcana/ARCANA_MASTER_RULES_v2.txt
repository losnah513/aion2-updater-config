ARCANA PROJECT MASTER RULES v2.1

[최상위 원칙]
1. 실제 결과물(ZIP) 없는 완료 보고 금지
2. 승인 없는 버전업 금지
3. 중간보고 최소화
4. 구조 분석 후 수정
5. 현실적인 제작 시뮬레이터 철학 유지
6. 작업 전 기존 작업물 감사 필수
7. 새 코드 덮어쓰기 금지: 수정/추가/삭제를 먼저 분류하고 중복 권한을 회수한 뒤 작업

[버전 관리]
- ARC 버전은 사용자 승인 시에만 변경
- 같은 버전 내 작업은 날짜/순번만 증가
- 파일명: arcana_ARC-버전_YYYYMMDD_순번.zip
- 순번 뒤 작업명/설명 추가 금지
- 웹 표기: ARC-버전 · YYMMDD_순번

[코드 작업 규칙]
- 작업 시작 전 기존 코드 검색/감사 필수
- 수정: 기존 파일/기존 권한이 있는 곳을 고친다
- 추가: 기존 권한이 없을 때만 새 파일을 만든다
- 삭제: 사용하지 않는 코드와 중복 권한 코드는 제거한다
- 파일 자체가 필요 없어졌을 때는 파일을 무작정 삭제하지 않고 legacy로 이동하거나 빈 파일로 유지하며 폐기 사유/이관 위치/폐기 버전을 기록한다
- 주석 처리만 하고 구 코드를 실행 파일에 방치하지 않는다

[권한 관리 규칙]
- 레이아웃 폭/높이/카드 BODY/FOOTER 권한은 arcana-layout-manager.css가 담당
- Prism/저장/선택/CTA 시각 효과 권한은 prism-aura.css와 필요한 JS 유틸이 담당
- 클래스 선택 UI/이벤트 권한은 classSelector 계열 파일이 담당
- 추천 CTA 권한은 arcana-cta 계열 파일이 담당
- cards.css/layout.css/main.css에 신규 레이아웃·효과 권한을 흩뿌리지 않는다

[추천 엔진 철학]
- 현실적인 최적 조합 우선
- 이론상 최고 조합보다 실제 제작 가능 조합 우선
- 목표 달성 후 남는 칸에 임의 스킬을 넣지 않는다
- 남는 추천 슬롯은 '스킬 여유'로 표시한다

[추천 엔진 우선순위]
1. 사용자 지정 20레벨 목표 달성
2. 사용자 지정 16레벨 목표 달성
3. 저장된 현재 아르카나 반영
4. 저장된 반지 옵션 반영
5. 아르카나만으로 목표 달성 시도
6. 부족분에 한해 자동 반지 활용
7. 21레벨 이상 초과 조합 폐기
8. 목표 달성에 꼭 필요한 경우에만 Lv4 사용
9. 스킬 포인트에 여유가 있으면 Lv4 강제 금지
10. 제작 난이도 최소화
11. 동일 조건 시 반지 사용 최소화

[스킬 레벨 계산]
- 기본 스킬 = 10
- 데바니온 = +4
- 기본 상태 = 14
- 16레벨 목표 = +2 필요
- 20레벨 목표 = +6 필요
- 21레벨 이상 = 금지
- 전체 예산: Lv5 아르카나 4개 36포인트 + 반지 6포인트 = 42포인트

[20/16 목표 예산]
- 20레벨 목표 7개 = 42포인트, 16레벨 추가 없음
- 20레벨 목표 6개 = 36포인트, 16레벨 최대 3개 가능
- 20레벨 목표 5개 = 30포인트, 16레벨 최대 6개 가능
- 20레벨 목표 4개 = 24포인트, 16레벨 최대 9개 가능
- 20레벨 5개 이하에서 16레벨 직접 지정이 부족하면 남는 포인트를 16레벨 목표에 자동 분산 가능

[Lv4 사용 규칙]
- Lv4 최소화는 목표 달성보다 우선하지 않는다
- 그러나 스킬 포인트가 충분하면 Lv4를 만들지 않고 3/2/2/1/1 등 분산을 우선한다
- Lv4는 목표 달성에 남은 부족분이 있고 다른 분산으로 달성하기 어려울 때만 사용한다
- 20레벨 목표가 7개일 때는 성배/양피지/나침반/천칭에 각각 4레벨 액티브 스킬이 최소 1개씩 필요하다
- 20레벨 목표가 6개 이하라면 모든 아르카나에 Lv4가 반드시 들어갈 필요는 없다

[반지 규칙]
- 저장된 반지 = 현실 데이터, 변경 금지
- 미저장 반지 = 자동 활용 가능
- 자동 반지 사용 순서: 20 달성 부족분 → 16 달성 부족분
- 목표 달성 후 남는 반지/아르카나 슬롯에 불필요한 스킬을 임의 삽입하지 않는다

[Lv5 아르카나]
- 기본 1/1/1/1
- 추가 포인트 +5
- 총합 9 필수
- 허용: 4/3/1/1, 4/2/2/1, 3/3/2/1, 3/2/2/2
- 폐기: 4/1/1/1, 총합 9 미만, 총합 9 초과

[아르카나 최신 데이터]
- 성배 = 액티브 F~Q + 패시브 F~O
- 천칭 = 액티브 F~Q + 패시브 F~O
- 양피지 = 액티브 F/H/J/L/O/P 총 6개
- 나침반 = 액티브 G/I/K/M/N/Q 총 6개
- 종 = 패시브 F/H/J/L/N 총 5개
- 거울 = 패시브 G/I/K/M/O 총 5개
- 모든 클래스는 같은 아르카나 규칙을 사용한다
- class_skill_db의 skill_db_ 접두어는 시트 DB 키로 유지한다
- 내부 표준 키와 화면 표시명은 별도 매핑한다

[분석 결과]
- 20 목표 / 16 목표 분리 출력
- 달성 = 초록 계열
- 미달성 = 부드러운 붉은 계열
- 목표 초과 = 조정 필요 안내
- 스킬 여유 슬롯은 목표 계산에 포함하지 않는다

[추천 가이드]
- 반지 교체 시 달성 가능 여부
- 필요 Lv4 개수
- 추가 제작 필요 아르카나
- 현재 조합 유지 가능 여부
- 목표 달성 후 남는 슬롯은 스킬 여유로 안내

[저장 시스템]
- 저장 후 '수정하기' 전환
- 저장된 현실 데이터는 임의 초기화 금지
- 저장하지 않은 임시 선택값은 새로고침/재접속 시 복원 금지
- UI 표시값과 내부 state가 불일치하면 분석 시작 금지

[CTA]
- 버튼명: 분석 시작
- Idle = 흑백/저채도 방사형 막대 파동
- Hover = 단색 유지 + 파동 강화
- Loading = 프리즘 컬러로 부드럽게 전환 + 분석중 텍스트
- 분석중 최소 5초 이상 유지
- 별도 모달 금지

[디자인/효과]
- 저장 완료 카드: 빗금, 채도 감소, 수정하기 전환, Prism Aura 외곽 흐름
- 20레벨 스킬: 골드/오팔 프리즘 계열
- 16레벨 스킬: 실버/라벤더 프리즘 계열
- 효과는 버튼/카드 내부에 갇혀야 하며 화면 전체로 새면 안 된다

[다음 채팅방 인수인계 확인]
1. ZIP 루트에 ARCANA_MASTER_RULES_v2.txt가 있는지 확인
2. 웹 루트 arcana/ARCANA_MASTER_RULES_v2.txt와 내용이 같은지 확인
3. MODIFIED_FILES.txt가 최신 순번인지 확인
4. index.html 버전 표기가 ZIP 파일명 순번과 맞는지 확인
5. Apps Script 수정 여부와 재배포 필요 여부 확인
6. 기존 코드 감사 없이 새 CSS/JS만 추가하지 말 것
