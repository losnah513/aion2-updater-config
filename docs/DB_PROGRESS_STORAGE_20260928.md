# 실행 진행률 저장 공간 재사용 · SQL521

2026-09-28 재점검에서 DB는 419,794,067B였다. 예약 정리는 실제로 데이터를 지우고 있었지만, 진행률 요약 305행의 누적 UPDATE가 약 103만 회였고 표가 18,497,536B로 커져 있었다. 단계 상세를 `phases`와 `progress_payload.phases`에 중복 저장하면서 작은 진행률 변경에도 큰 JSON을 재작성했다.

## 변경

- 단계 상세의 1,024B 초과 값은 순서가 같은 `phase_details_v521` 배열에 한 번 저장한다. 작은 카운터와 단계 상태는 기존 `phases`에 둔다. 조회 함수가 완전한 기존 JSON 응답을 재구성한다.
- UPDATE에서 값이 동일한 JSON은 OLD 값을 사용해 기존 TOAST 저장 공간을 재사용한다. 변경된 큰 값은 정상 반영하며 `updated_at` 갱신을 생략하지 않는다.
- 기존 두 사본이 정확히 같은 행만 변환한다. 운영 305/305행이 변환됐고, 잠금이 유지되는 동일 트랜잭션에서 소유자 레벨4·비소유자 레벨4·레벨5의 전체 응답 해시 915개가 일치했다. 불일치하면 마이그레이션 전체가 취소된다.
- summary/snapshot/payload의 heap 및 TOAST 자동 VACUUM 기준을 2%·50행으로 낮추고 분석 기준을 5%로 설정했다. 자동 VACUUM은 빈 공간 재사용을 돕고, 물리 파일 축소를 매번 보장하지는 않는다.
- 새 공개 RPC와 권한 확대는 없다. 새 private helper는 postgres만 실행한다. Security Advisor 기존 5개 항목은 전후 동일하며 신규 항목은 없다.

## 검증과 복구

`node tests/progress-storage-reuse.test.cjs`는 기존 실함수와 새 함수를 별도 PGlite에서 실행한다. 40번의 동일 카운터 갱신에 추가 공간이 8,290,304B → 32,768B로 감소했다(99.60%). 이는 해당 재현 시나리오의 쓰기 증가분이며 전체 DB 증가율 감소를 뜻하지 않는다. 전체 조회 응답, null/누락/배열/문자열 상세, 불일치 구형 행 보존, 실제 큰 값 변경 반영, 권한 및 rollback이 통과했다. 기존 완료 상세 보존·명부 자동 실행 테스트도 통과했다. CI에 새 회귀를 추가했다.

Rollback은 분리한 상세를 기존 두 위치에 복원한 뒤 원래 함수와 저장 옵션을 되돌린다. 이 구조 변경은 상세 데이터를 삭제하지 않는다. 마이그레이션과 rollback은 각각 `supabase/migrations/20260928050552_progress_storage_reuse.sql`, `supabase/rollbacks/20260928050552_progress_storage_reuse.sql`이다.

## 운영 정리

- 세 주요 표의 단발성 VACUUM FULL은 05:17:00~05:17:32 UTC 성공했다. summary 6,709,248B, snapshot 73,646,080B, payload 40,091,648B로 전체 DB 395,111,571B를 확인했다. 해당 임시 예약은 해제했다.
- 새로 30일을 경과한 완료 실행 1개의 상세를 기존 SQL511로 정리했다: 이벤트490, Target154, Step10, 완료 큐146. 기존 보존 조건을 변경하지 않았다.
- 나머지 관리자 상세·접수·큐·cron 표의 단발성 VACUUM FULL도 05:19:00~05:19:07 UTC 성공했다. 최종 DB **388,320,403B**, 시작보다 **31,473,664B 감소**, 390,000,000B 목표보다 **1,679,597B 작다**. 임시 예약 잔여0, summary305·snapshot17,322·payload16,636행 불변을 확인했다.
- 운영 브라우저 로그인 검수는 수행하지 않았다. 위 응답 비교는 DB 내부 함수 계약 검증이며 사용자 인증 검수를 대체하지 않는다.

기존 주·월 성장 수치와 현재 원본 참조 보호는 유지한다. 전체 원본 7일 정책의 남은 참조 분리 작업과 며칠 동안의 실제 용량 안정성 관측은 별도 후속이다.
