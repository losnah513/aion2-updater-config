ARCANA PROJECT MASTER RULES v3.0

[역할]
ARCANA 프로젝트는 아르카나 스킬 시뮬레이터 유지보수 프로젝트다.
목표는 기존 기능을 안정적으로 유지하면서 개선하는 것이다.
새 기능 추가보다 기존 구조 보호, 중복 제거, 권한 회수를 우선한다.

[작업 절차]
사용자가 수정/기능 추가를 요청하면 바로 코딩하지 않는다.
순서:
1. 수정 내용 확인
2. 원인 분석
3. 해결 방안 모색
4. 해결 방법 제시 리포트
5. 사용자 승인
6. 기존 작업물 감사
7. 수정 / 추가 / 삭제 분류
8. 권한 회수
9. 실제 수정
10. 검수
11. 결과물 ZIP 생성

[날짜/순번 루틴]
작업 시작 전 오늘 날짜와 오늘 작업 순번을 확인한다.
WORK_LOG / MODIFIED_FILES / 최신 ZIP을 확인해 순번을 결정한다.
추측으로 순번을 정하지 않는다.
ZIP 파일명: arcana_ARC-버전_YYYYMMDD_순번.zip
순번 뒤 설명 문구는 붙이지 않는다.
화면 표기: ARC-버전 · YYMMDD_순번

[코드 정리 규칙]
새 CSS/JS를 덮어쓰기식으로 추가하지 않는다.
기존 코드 위치를 먼저 찾고, 수정/추가/삭제로 분류한다.
사용하지 않는 코드는 삭제한다.
필요 없어지는 파일은 삭제하지 말고 legacy 처리하거나 빈 파일로 유지하며 폐기 사유/이관 위치를 기록한다.

[레이아웃 권한]
레이아웃 권한은 arcana-layout-manager.css가 담당한다.
페이지 폭, CARD-01~05 배치, 카드 높이, 내부 title/message/tab/body/footer, 공통 버튼 규격은 이 파일에서 관리한다.
다른 CSS에서 중복 관리하지 않는다.

[CARD 분류]
CARD-01 액티브 스킬 선택
CARD-02 반지 스킬 옵션
CARD-03 기능 추가 예정 영역
CARD-04 현재 아르카나
CARD-05 추천 아르카나
PC 기준: 1/2/3은 1:1:1, 4/5는 1:1. 윗줄과 아랫줄 좌우 끝선은 같아야 한다.

[Prism Aura 권한]
효과 권한은 prism-aura.css가 담당한다.
스킬 클릭 푸딩, 16/20 스킬 버튼 테두리, 저장 완료 빗금/채도감소/테두리 흐름, CTA 색감 보조를 관리한다.
테두리를 따라 빛이 돌아야 하며, 버튼/카드 뒤에서 큰 레이어가 회전하면 안 된다.
Lv/중요도 뱃지는 스킬명을 덮지 않는다.

[저장 상태]
저장 완료 시 빗금 배경, 채도 감소, 수정하기 버튼 전환, 카드 테두리를 따라 흐르는 Prism Aura를 적용한다.
대상: 액티브 스킬, 반지 옵션, 현재 아르카나.

[CTA]
버튼명은 분석 시작.
CTA는 방사형 막대 + 불규칙 파동 외곽.
대기: 흑백 느린 파동.
롤오버: 단색 유지 + 속도 증가.
분석중: 부드러운 컬러 전환 + 최소 5초 유지.

[클래스 선택]
상단 클래스 선택 버튼은 1개만 존재.
클릭 시 카드 회전형 모달을 연다.
확인 버튼 전까지 클래스 변경을 반영하지 않는다.

[추천 엔진]
기본 10 + 데바니온 4 = 기본 14.
20레벨 목표는 +6, 16레벨 목표는 +2.
아르카나 36 + 반지 6 = 총 42포인트.
목표 달성 후 남는 슬롯에 임의 스킬 삽입 금지. '스킬 여유'로 표시.
Lv4는 필수일 때만 사용하고 여유가 있으면 분산 투자 우선.
20레벨 7개일 때만 성배/양피지/나침반/천칭 Lv4 앵커 조건 적용.

[아르카나 매핑]
성배 = 액티브 F~Q + 패시브 F~O
양피지 = 액티브 F/H/J/L/O/P
나침반 = 액티브 G/I/K/M/N/Q
종 = 패시브 F/H/J/L/N
거울 = 패시브 G/I/K/M/O
천칭 = 액티브 F~Q + 패시브 F~O

[검수]
F5, Ctrl+F5, 클래스 선택/변경, 저장/수정, 분석 시작, 분석중 최소 5초, 추천 결과 탭, Lv/중요도 뱃지, 저장 효과를 확인한다.

[결과 보고]
수정 파일, 추가 파일, 삭제/legacy 파일, 검수 항목, Apps Script 수정 여부와 재배포 필요 여부를 보고한다.
