KINOJO CORE 연결 정리 리포트
버전: Kinojo_1_3_1_17_20260623_22

1. 작업 원칙
- core 폴더 삭제 금지.
- 공통 기능 파일을 실제 운영 페이지에서 로드하고 사용할 수 있도록 연결한다.
- 페이지별 기존 로직은 한 번에 대량 삭제하지 않고, 공통 엔진을 먼저 활성화한 뒤 단계적으로 이전한다.

2. 활성화한 core 파일
- core/kinojo-api.js
  Apps Script GET/POST/action 호출 공통 래퍼로 구현.
- core/kinojo-cache.js
  메모리/sessionStorage TTL 캐시 공통 엔진으로 구현.
- core/kinojo-permissions.js
  ROLE/LEVEL/권한 판단 공통 엔진으로 구현.
- core/kinojo-toast.js
  공통 토스트 알림 엔진으로 구현.
- core/kinojo-modal.js
  공통 안내/확인/로그인 연결 모달 엔진으로 구현.
- core/kinojo-route-guard.js
  로그인/권한 필요 기능 접근 제어 보조 엔진으로 구현.
- core/kinojo-debug.js
  ?debug=1 기반 진단 로그 엔진으로 구현.
- core/kinojo-logger.js
  공통 운영 로그 보조 엔진으로 구현.

3. 실제 로드 연결
아래 운영 페이지에 core 공통 파일들을 kinojo-auth.js 및 kinojo-common-ui.js보다 먼저 로드하도록 연결함.
- home.html
- arcana/index.html
- hof/index.html
- m/index.html
- m/hof/index.html
- sanctuary/index.html
- m/sanctuary/index.html

4. 실제 사용 연결
- kinojo-auth.js
  apiUrl, 로그인 POST, 코드 요청 POST, 회원관리 POST를 KinojoApi 우선 사용으로 변경.
  역할/등급 판단을 KinojoPermissions 우선 사용으로 변경.
  알림은 KinojoToast 우선 사용 유지.
- kinojo-common-ui.js
  공지사항 조회, 방문자수 조회, 공통 토스트를 KinojoApi/KinojoToast 우선 사용으로 변경.
- kinojo-admin-panel.js
  MVP, 성장왕, 트리거, 방문자수, 공지 등록 API 호출을 KinojoApi 우선 사용으로 변경.

5. 아직 단계적 이전이 필요한 영역
- hall-data.js / hall-reactions.js / hall-suggestions.js
  일부 fetch 직접 호출 유지. 다음 단계에서 KinojoApi로 이전 가능.
- sanctuary.js / sanctuary-editor.js / sanctuary-capture.js
  성역 전용 복사/수정/캡처 흐름은 안정화 후 단계적으로 공통 엔진 연결 권장.
- arcana/js/api.js / confirmModal.js
  ARCANA 전용 구조가 있어 별도 검수 후 공통 모달/API로 부분 이전 권장.

6. 삭제 없음
이번 작업에서는 core 파일 삭제 없음.
구버전 auth.js/config.js 등 확장프로그램용으로 보이는 파일도 삭제하지 않음.
